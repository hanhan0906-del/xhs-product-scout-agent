## 0. 这份项目板的作用

这是本项目从“当前状态”走到“真正完成”的唯一执行指南和完成度入口。

- `HANDOFF.md`：记录真实运行状态、关键决策、历史证据和接手步骤。
- `ROADMAP.md`：解释技术阶段和长期方向。
- `coordination/KEYWORD_STRATEGY.md`：关键词来源、拆解、组合、审核和轮转的唯一现行策略。
- `coordination/NEXT_CONTROL_HANDOFF.md`：新总控的最小上下文入口，避免开局通读全部历史。
- `PARALLEL_WORK.md`：仅作为历史并行任务运行日志，不再承担项目总表作用。
- 本文件：决定接下来做什么、为什么做、优先级、依赖、预计耗时、能否分派和怎样验收。

任何任务在执行或分派前，必须先出现在本板中。任务状态变化后，先更新本板，再安排下一项。

## 1. 最终目标与边界

### 1.1 最终目标

建立一个高覆盖、低频、可暂停、可审计的小红书虚拟商品选品平台：

1. 从用户确认的主发现词 `虚拟资料` 出发，小批搜索公开虚拟商品；
2. 只有商品详情页至少出现 3 个不同有效灰色指标条，才进入总控台；
3. 从达标商品标题拆解人群、类别、场景、形态、阶段和功能词元，迭代下一批种子词；
3. 通过 Android 11 BlueStacks Rvc64 正常浏览小红书公开页面；
4. 采集商品身份、真实链接、公开趋势指标、相关公开笔记和公开账号证据；
5. 把数据、证据和运行状态写入本地数据库及证据目录；
6. 识别“低粉爆款”，输出候选分析、风险、证据缺口和原创化改写方向；
7. 经过完整 G0–G5 验证后，实现可安全停止、可恢复、可审计的 24 小时自动监控；
8. 24 小时通过后再评估扩大到每轮 3–5 个关键词，不自动扩容。

### 1.2 明确不做

- 不宣称穷举或覆盖小红书全站、全部类目和全部商品；
- 不使用隐藏接口、抓包解密、私密数据、代理池、多账号或设备伪装；
- 不绕过验证码、登录、安全限制或平台风控；
- 不使用 Magisk、Xposed、LSPosed，不处理 Pie64_2 限制为可绕过问题；
- 不发布，不购买，不加购，不收藏，不关注，不评论，不联系客服；
- 不自动安装 Windows 计划任务；安装前必须获得用户明确确认。

### 1.3 低粉口径

- 核心低粉：公开有效粉丝数 `1–1000`；
- 临界低粉：公开有效粉丝数 `1001–2000`；
- `0` 表示证据缺失，绝不能当成真实低粉；
- A 级必须同时有商品热度、近期公开笔记、单条笔记互动、作者一致性和公开粉丝数；
- 缺任一关键证据时保持 B/C 或 `needs_review`，不得自动冒充 A 级。

## 19. 分派原则

### 必须由总控串行执行

- 生产数据库写入；
- 8793/8765 所有权操作和服务重启；
- ADB、BlueStacks、小红书真实 UI；
- 真实采集、补证、scheduler、pre-soak、24h soak；
- 关键词批准后的生产入队；
- HANDOFF 和本项目板的最终更新；
- Windows 计划任务安装。

### 可以精确分派的局部任务

- 纯离线算法或独立新模块；
- 只读报告/质量审计；
- 临时数据库上的定向测试；
- 不修改现有源码的集成回归；
- 文档初稿；
- 当前批次完成后的证据汇总。

每个子任务只能读取完成局部工作需要的少量文件；不得通读全部项目、完整 HANDOFF、完整本板和所有专项文档。

默认只使用“总控 + 最多 1 个子任务”。只有两项确实独立、写入范围无冲突且都直接推动当前 P0/P1 主线时，才临时提高到 2 个子任务。
